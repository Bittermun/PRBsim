# Project working memory

The user wants the assistant to maintain project memory, including what went right, what went wrong, and what remains uncertain. Reference codes are for the assistant's continuity; the user may speak in ordinary language.

- At the start of substantive project work, consult `docs/prb/INDEX.md` and the latest entry in `docs/prb/WORK_LOG.md`. Consult the linked development review when its findings affect the task.
- Preserve existing reference-code meanings and prior outcomes. Use codes internally to connect concepts, methods, findings, and follow-up work.
- After meaningful research or implementation, record the question, action taken, evidence, successes or failures, corrections, unresolved points, and next useful check in the work log. Keep the index current when a new strategy or lesson is established.
- Distinguish a proposal, documented capability, reproduced behavior, implemented feature, and scientifically validated result. Carry forward the date and scope of prior checks; do not present an old test result as a new run.
- Explain conclusions to the user in plain language unless technical detail is requested. Do not require the user to learn the reference codes.
